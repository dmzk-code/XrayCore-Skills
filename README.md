# Xray-core Skills

**Набор скиллов для ИИ-агентов: создание, аудит и проверка сложных конфигураций Xray-core на основе документации и исходного кода.**

Пакет предназначен для работы с Claude Code, Codex и другими агентами, способными читать инструкции `SKILL.md` и связанные справочники. Вместо одного большого промпта используется общий скилл-координатор и отдельные специализации по транспортам, протоколам, безопасности и диагностике.

**17 скиллов · 9 транспортов · 8 общих специализаций · 45 базовых конфигурационных шаблонов**

> [!IMPORTANT]
> Это независимый пакет знаний и вспомогательных инструментов, а не сборка, форк или патч Xray-core. Он не устанавливает ядро и не изменяет рабочие серверы автоматически. Успешная статическая проверка не означает успешного соединения или готовности конфигурации к эксплуатации.

## Возможности

**Создание конфигураций.** Согласованные клиентские, серверные и промежуточные узлы; выбор транспорта и защиты; сложные цепочки соединений; раздельные upload/download-плечи XHTTP; схемы с обратным прокси и завершением TLS на нём.

**Проверка параметров.** Типы, значения по умолчанию, роли клиента и сервера, приоритеты альтернативных полей, различия между отсутствующим полем, `null`, нулём и пустым значением. Отдельно рассматриваются параметры, которые принимаются парсером, но не применяются выбранным обработчиком.

**Общая инфраструктура.** DNS, маршрутизация, балансировка, проверки доступности, Mux/XUDP, TLS/REALITY, ECH, настройки сокетов, Finalmask, API, Metrics, статистика, логи и политики ресурсов.

**Аудит и миграция.** Проверка действующей авторизации, совместимости сторон, конфликтов слушателей и тегов, циклов соединений, объединения нескольких файлов и переноса старых конфигураций с сохранением возможности отката.

**Воспроизводимые проверки.** Статический валидатор, локальные лабораторные сценарии, отрицательные проверки авторизации, передача полезных данных, переподключение и отчёты с разделением фактического результата и предположений.

### Как устроена база знаний

Правила рассматриваются по цепочке:

```text
JSON → разбор конфигурации → Build() → обработчик клиента/сервера → поведение соединения
```

Наличие поля в документации, Go-структуре или protobuf само по себе не считается доказательством его действия. Пакет различает правила сборки конфигурации, поведение обработчиков, результаты конкретных испытаний и более строгие рекомендации безопасной генерации.

Основные документы: [общий контракт](skills/xray-config-orchestrator/references/contract.md), [карта знаний](skills/xray-config-orchestrator/references/knowledge-map.md), [совместимость](skills/xray-config-orchestrator/references/compatibility.md), [топология и слушатели](skills/xray-config-orchestrator/references/topology-and-listeners.md).

## Установка

### Требования

| Компонент | Когда нужен |
|---|---|
| Агент, умеющий читать `SKILL.md` | Для использования инструкций и справочников. |
| Python 3.10+ | Для установщика, валидатора и вспомогательных скриптов. |
| Зависимости из `requirements-crypto.txt` | Необязательно: для локальной сверки поддерживаемых X25519-пар. |
| OpenSSL | Для генерации сертификатов в лабораторных сценариях. |
| Доверенный бинарник Xray и его SHA256 | Только для проверок с исполнением ядра. |
| Nginx | Для лабораторных схем, которые используют этот обратный прокси. |

Нативные испытания пакета выполнены на Linux. Наличие платформенных правил в справочнике не означает, что все инструменты и сетевые сценарии испытаны на каждой ОС.

### Проверка пакета

Получите доверенный релизный архив и проверьте его SHA256 по независимо полученному значению **до запуска любых файлов из архива**. Распакуйте его в отдельную папку, вне целевого каталога скиллов, затем выполните из корня распакованного пакета:

```bash
python verify_package.py
```

> [!NOTE]
> `SHA256SUMS.txt` проверяет согласованность содержимого, но не является цифровой подписью издателя. Проверяющие инструменты r6 ожидают чистую распакованную поставку: каталог `.git` и посторонние файлы могут вызвать ошибку manifest. Установку и проверки целостности выполняйте из релизного архива, а не непосредственно из рабочего Git-checkout.

### Claude Code или Codex

Выберите каталог нужного проекта и один из вариантов установки:

```bash
# Claude Code
python install.py --target "/absolute/path/to/project/.claude/skills" --replace

# Codex
python install.py --target "/absolute/path/to/project/.agents/skills" --replace
```

В Windows используйте `py -3` вместо `python`:

```powershell

# Codex
py -3 install.py --target "C:\Projects\my-project\.agents\skills" --replace
```

Замените пути на свои. Установщик проверяет manifest, сохраняет резервные копии заменяемых одноимённых скиллов и не удаляет посторонние скиллы. Существующие `AGENTS.md` и `CLAUDE.md` не перезаписываются. Для включения правил в проект предусмотрен [`AGENTS.example.md`](AGENTS.example.md).

Файловая установка и работа установленного CLI проверены; автоматическая активация скиллов в интерфейсе конкретного агента отдельно не измерялась.

### Необязательная проверка X25519-ключей

```bash
python -m pip install -r requirements-crypto.txt
```

Без этой зависимости соответствующая проверка получает предупреждение о неподтверждённом соответствии ключей. Остальные доступные проверки не должны интерпретироваться как доказательство корректности ключевой пары. Зависимости автоматически не устанавливаются.

## Использование

Основной скилл — **`xray-config-orchestrator`**. В задаче укажите версию ядра, роли узлов, особенности сети и требуемую схему. Для изменения существующей конфигурации приложите исходные файлы и обозначьте, что необходимо сохранить.

### Создание сложной конфигурации

```text
Используй xray-config-orchestrator и необходимые транспортные скиллы.

Собери согласованные конфигурации клиента и сервера для XHTTP
с раздельными upload/download-плечами и Nginx перед сервером.

Проверь эффективные настройки, режимы XHTTP, HTTP-версию, TLS,
владельца сессии, заголовки, лимиты и маршруты обоих плеч.

Верни полные конфигурации сторон и Nginx, схему соединений,
обоснование нестандартных параметров и результаты выполненных проверок.
Незапущенные проверки пометь NOT_RUN. Рабочие сервисы не изменяй.
```

### Аудит существующей схемы

```text
Используй xray-config-orchestrator, xray-source-audit
и xray-runtime-validation.

Проанализируй приложенные конфигурации и логи по закреплённой версии.
Проверь действующую авторизацию, совместимость сторон, транспорт,
защиту, DNS, теги, слушатели и известные ограничения ядра.

Не меняй архитектуру без необходимости. Верни минимальный diff,
полные исправленные файлы, подтверждённые причины ошибок
и безопасный порядок применения с возможностью отката.
```

Дополнительные варианты заданий находятся в [`PROMPTS.md`](PROMPTS.md). Версию для конкретной задачи сверяйте с `VERSION.lock.json` и установленным ядром, а не с историческими заголовками примеров.

### Ожидаемый результат работы агента

Для сложной схемы общий контракт предусматривает следующий комплект:

```text
client.json          # Конфигурация клиента
server.json          # Конфигурация сервера
relay-*.json         # Промежуточные узлы, когда они нужны
topology.json        # Описание схемы соединений
peer-map.md          # Согласование параметров сторон
ASSUMPTIONS.md       # Допущения и незаданные параметры
VALIDATION.json      # Результаты фактически выполненных проверок
rollout.md           # Применение изменений и откат
```

При наличии обратного прокси добавляется его конфигурация, при изменении существующих файлов — diff. Это формат ожидаемой выдачи агентом, а не обещание, что одна команда валидатора автоматически создаёт весь комплект. Шаблоны с незаполненными значениями не предназначены для развёртывания.

## Инструменты проверки

Команды ниже выполняются из корня чистой распакованной поставки. Имена файлов и тегов в примерах замените на свои.

### Проверка одного файла и пары

```bash
# Один полный конфигурационный файл
python skills/xray-source-audit/scripts/validate.py client.json --json

# Согласование сторон без предположения о прямом соединении
python skills/xray-source-audit/scripts/validate.py client.json --peer server.json --json
```

Когда между выбранными узлами действительно нет NAT, обратного прокси, завершения TLS или изменения портов:

```bash
python skills/xray-source-audit/scripts/validate.py client.json --peer server.json --outbound-tag PROXY --inbound-tag INBOUND --direct-peer --json
```

`--direct-peer` — явное утверждение о топологии, а не способ автоматически проверить неизвестную сеть. При наличии посредников проверяйте каждое плечо отдельно. Статус `PASS_STATIC_ONLY` подтверждает только статический этап.

### Объединение нескольких конфигураций

```bash
python skills/xray-source-audit/scripts/compose_config.py -c 00-base.json -c 20-proxy.json --confdir ./conf.d
```

Сборщик учитывает правила `Config.Override`, а не произвольное рекурсивное объединение JSON. По умолчанию он не выводит полный объединённый конфиг с секретами. Для явной записи в **новый приватный файл**:

```bash
python skills/xray-source-audit/scripts/compose_config.py -c 00-base.json -c 20-proxy.json --write-merged new-merged.json
```

Не публикуйте такой файл без удаления реквизитов. Подробности: [объединение конфигураций](skills/xray-config-orchestrator/references/composition.md).

### Тесты инструментов и нативные сценарии

```bash
# Собственные тесты пакета
python -m unittest discover -s tests -v

# Проверки пакета через CI entry point, без запуска ядра
python ci/verify.py --out /absolute/path/to/new-private-ci-output
```

Нативная серия r6 запускается отдельно и требует доверенного SHA256 бинарника:

```bash
python skills/xray-source-audit/scripts/run_r6_regressions.py --xray /absolute/path/to/xray --sha256 TRUSTED_BINARY_SHA256 --execute --out /absolute/path/to/new-private-r6-output
```

`TRUSTED_BINARY_SHA256` необходимо заменить на ожидаемый SHA256 из доверенного источника. Рабочий каталог результатов должен быть новым и находиться вне поставки. Лабораторные данные могут содержать сгенерированные секреты — целиком публиковать их нельзя.

Состав остальных серий, параметры сборки и Go-тестов описаны в [`ci/README.md`](ci/README.md). `ci/verify.py` — локальная точка запуска проверок, **не уже настроенный GitHub Actions workflow**.

| **L3** | Установление соединения, полезный TCP/UDP-трафик и отрицательная авторизация. |
| **L4** | Перезапуски, переподключение и отказы отдельных частей схемы. |
| **L5** | Длительная нагрузка, ресурсы, задержки, доля ошибок и целевая платформа. |

Пакет не повышает статический результат до сетевого. В отчётах и справочниках отдельно используются `SOURCE_BUILD`, `SOURCE_RUNTIME`, `OBSERVED_RUNTIME`, `INFERENCE`, `AUTHORING_POLICY` и `NOT_RUN`. Политика безопасной генерации может быть строже парсера ядра.

## Известные особенности и ограничения

| Область | Что необходимо учитывать |
|---|---|
| **gRPC** | В закреплённой версии воспроизведён отказ восстановления после перезапуска сервера. Наличие пустого `finalmask` или только `quicParams` не доказывает обход проблемной ветки. |
| **SOCKS/mixed** | `auth: "password"` с пустым эффективным списком учётных записей не гарантирует закрытие HTTP-ветки того же слушателя. Опасные варианты отвергаются валидатором. |
| **TLS с uTLS** | Для исследованных веток наличие `minVersion`/`maxVersion` в JSON не гарантирует применения этих границ клиентом. В базе сохранён разбор фактического переноса настроек. |
| **XHTTP через HTTP/1.1** | В предыдущих сериях наблюдались отдельные отказы короткой нагрузки после перезапуска. Они не объявлены исправленными и не распространяются автоматически на все режимы XHTTP. |
| **Внешняя инфраструктура** | Локальная проверка не подтверждает права облачного аккаунта, лимиты провайдера, поведение CDN, NAT или произвольного обратного прокси. |

Подробности и доказательства: [`known-issues.md`](skills/xray-runtime-validation/references/known-issues.md).

В r6 не выполнялись сборка ядра из исходников, Go-suite, нативные испытания на Android/macOS/Windows, проверка активации в интерфейсе агента и длительная нагрузка. Реестр не заявлен полной JSON Schema всего Xray-core и всех зависимостей.

## Безопасность

Не публикуйте приватные ключи, пароли, OAuth-токены, полные ссылки подписок, рабочие конфигурации и необработанные журналы. Сгенерированные лабораторные секреты также не должны попадать в публичный репозиторий или CI artifacts.

Локальный стенд использует отдельные процессы и тестовые адреса, но не является полноценной системной песочницей. Запускайте только доверенный бинарник; проверка его хеша не делает недоверенный код безопасным. Изменение firewall, системных маршрутов и рабочих сервисов не входит в обычную генерацию конфигурации.

Для применения изменений на сервере сохраняйте рабочий комплект, отдельный путь административного доступа и порядок отката. Правила описаны в [общем контракте](skills/xray-config-orchestrator/references/contract.md) и [описании лабораторной среды](skills/xray-runtime-validation/references/lab-environment.md).

## Развитие и обновление

При смене версии ядра нужно сопоставить изменения исходников, пересмотреть затронутые правила, добавить регрессионные проверки и обновить версионный lock. Простая замена номера версии в тексте не обновляет базу знаний.

При сообщении об ошибке приложите версию и SHA256 ядра, ОС, обезличенную минимальную конфигурацию, ожидаемое и фактическое поведение, команду проверки и очищенный отчёт. Для изменения правил желательно указать конкретный исходник и добавить положительный и отрицательный тест.

Перед публикацией изменённой поставки обновляйте `SHA256SUMS.txt` и проверяйте чистый релизный архив. Manifest относится ко всему составу файлов, включая `README.md`; не отключайте проверку целостности ради установки изменённого пакета. Исторические результаты испытаний должны оставаться историческими.
